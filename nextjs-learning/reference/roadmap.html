Reference · Job-ready path

Next.js roadmap (MERN → hireable)

Ordered for ~4 hrs/day. Build different app types on purpose — each one forces a different interview story.

Tied to MISSION.md Primary course: Dashboard App

Phase A — Mental model (Days 1–3)

Goal: stop thinking “React SPA + Express API by default.”

  1. App Router file conventions (app/, layouts, pages)
  2. Server vs Client Components (default server)
  3. Navigation with Link + nesting layouts
  4. CSS strategy (Tailwind or CSS Modules)
  5. next/image, next/font, metadata basics

Interview win: explain why Server Components reduce client JS and keep secrets on the server (docs).

Ship: marketing / portfolio site (multi-route, SEO metadata).

Phase B — Official full-stack pass (Days 4–12)

Work through the official Dashboard course end-to-end. Do not skip streaming, search params, Server Actions, errors, auth, metadata.

Course theme Interview angle
Fetching in Server Components vs useEffect + API call in SPA
Static vs dynamic rendering when HTML can be cached vs must be request-time
Streaming / loading.tsx perceived performance without CSR spinners only
Server Actions + revalidation mutations without a hand-rolled REST layer
Auth + Proxy protecting routes; session on server

Ship: finish the course app; deploy it; write a 1-page “how it works” README for interviews.

Phase C — Portfolio apps (Weeks 3–6)

One app type at a time. Each must demo a different capability.

# App type Forces you to practice
1 Content site / MDX blog static generation, metadata, OG images, content routes
2 CRUD dashboard (Mongo OK) Server Actions, validation, loading/error UI, search params
3 Auth-gated product (notes / jobs / expenses) Auth.js (or current recommended), protected routes, env secrets
4 Public API + UI (or Route Handlers for webhooks) when route.ts is justified vs Server Actions
5 (stretch) Storefront-lite or multi-tenant admin caching, revalidation, image perf, real UX polish

Phase D — Interview loop (ongoing from week 3)

  • For each shipped app: draw the request path on paper (browser → RSC → DB)
  • Practice answers: SSR/SSG/CSR, RSC vs Client, caching/revalidate, Server Actions vs REST
  • MERN translation drill: “I’d put this in Express; in Next I’d put it in ___ because ___”
  • Mock: 20-minute walkthrough of one project as if to a hiring panel

Daily 4-hour template

  1. 45–60 min — lesson / docs chapter (retrieval: close the tab and restate)
  2. 2–2.5 hrs — build / course chapter in code
  3. 30–45 min — interview write-up: 5 bullets “what I’d say”

Do not prioritize yet

  • Pages Router deep dive
  • Monorepos, microfrontends
  • Kubernetes / heavy infra
  • Perfect TypeScript before shipping
