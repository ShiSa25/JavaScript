Server vs Client Components

The single biggest shift from MERN SPA thinking. Get this wrong and every Next.js app becomes “React with extra steps.”

Mission: job-ready Next.js Primary source: Next.js docs — Server and Client Components

Why this lesson

In MERN you often ship a Client React app that calls Express. In the App Router, components are Server Components by default. You only opt into the client when you need browser capabilities. Official docs: Server and Client Components.

The rule (commit this)

Use Server Components when you need… Use Client Components when you need…
Fetch near the data source / DB State & event handlers (onClick, …)
Keep API keys & secrets off the browser Lifecycle effects (useEffect)
Less JavaScript sent to the client Browser APIs (window, localStorage)
Better FCP / stream UI progressively Custom hooks that depend on the above

MERN trap: putting "use client" on layout.tsx / whole pages “so hooks work.” That pulls a huge module graph into the client bundle. Prefer a small interactive leaf (e.g. LikeButton) and keep the page a Server Component.

Composition pattern to memorize

Server page fetches data → passes serializable props into a Client leaf for interactivity (from the official example): 

// app/[id]/page.js  — Server Component (default)
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const { id } = await params
  const post = await getPost(id)

  return (
    <main>
      <h1>{post.title}</h1>
      <LikeButton likes={post.likes} />
    </main>
  )
}

// app/ui/like-button.js  — Client Component
'use client'
import { useState } from 'react'

export default function LikeButton({ likes }) {
  const [count, setCount] = useState(likes)
  return (
    <button onClick={() => setCount(count + 1)}>{count} likes</button>
  )
}

What happens on first load (interview sketch)

  1. Server renders Server Components → RSC Payload
  2. Client Components + payload are used to prerender HTML
  3. Browser shows HTML quickly, then hydrates Client Components
